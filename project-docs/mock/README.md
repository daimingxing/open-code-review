# 开发测试与复测命令

本目录长期保存开发过程中实际使用的测试命令和复测说明，方便开发者直接重跑。目录名沿用 `mock`，内容同时覆盖受控模型测试、真实模型验收和人工复测，不限定为模拟服务或假数据。

## 记录方式

- 每个已有测试主题使用一个简短英文名的 Markdown 文件，在下方索引登记；只有实际需要记录命令时才新增主题文件。
- 开发、修复或验收中形成有复用价值的测试命令后，记录到对应主题；同一场景更新原条目，不按每次运行重复追加整套命令。
- 使用 PowerShell 7 命令块，写明工作目录、所测程序的启动方式与版本或源码提交。区分安装的 CLI 和本地构建产物，确保重跑测到同一实现。
- 提供完整执行顺序与必要变量赋值；可运行条目不使用省略号代替必要参数。模型凭据由已有配置或环境提供，文档不保存密钥。
- 测试仓库、Skill 和知识库的选择以[资源索引](../review-resources.md)为准；命令中为便于复制执行可保留必要路径，并在资源变更后复核。

## 每个场景记录的内容

| 内容 | 要求 |
|---|---|
| 测试目的 | 说明验证的用户行为与适用场景 |
| 执行前提 | 工作目录、程序版本、依赖、规则与 MCP 配置、所需模型；涉及真实审查时标明模型调用 |
| 测试输入 | 仓库、完整提交或明确范围、规则与知识版本；工作区测试记录快照或样例准备方式 |
| 复测命令 | 复制执行的命令及变量；有准备、执行和清理步骤时按顺序提供 |
| 结果判定 | 预期退出状态、关键输出及产物位置；明确检查什么才算通过 |
| 验证记录 | 最近执行日期、实际退出状态、通过或失败的现象，以及相应日志或证据位置 |

## 验证状态

- **已验证**：实际执行过，并满足记录的预期结果；标明日期和版本。
- **待验证**：尚未执行，或实现、配置、输入变化后尚未复核；不能标为已可用。
- **失败复现**：明确记录失败命令、预期与实际差异，供修复及回归使用。

产品计划中的命令留在功能 Spec；只有需要复测的具体场景才记入本目录。临时目录中的旧脚本或日志必须先确认仍可获取，才能作为复测依赖；大型产物不作为命令文档直接堆积。
