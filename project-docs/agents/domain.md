# 领域文档

本项目采用单一领域布局，领域术语和架构决策分别保存在根目录 `GLOSSARY.md` 与 `project-docs/adr/`。

## 读取时机

- 探索代码或使用领域概念前，读取根目录 `GLOSSARY.md`。
- 开展设计或实现前，读取 `project-docs/adr/` 中涉及当前范围的架构决策记录（ADR）。
- 文件或目录尚不存在时直接继续，不提前创建空文件或提示补齐；在术语或决策实际确定后，由 `domain-modeling` 按需创建。

## 使用与维护

- 任务标题、方案、假设和测试名称使用术语表中的统一名称，避免使用其中明确排除的同义词。
- 遇到未收录概念时，先判断是否可以复用现有术语；确有缺口时交由 `domain-modeling` 补充。
- 提议与既有 ADR 冲突时，明确指出对应记录及重新讨论的理由。
- 架构决策文件使用递增编号和简短英文名称，例如 `project-docs/adr/0001-report-material-format.md`；示例不代表已有决策。
- `project-docs/project-design.md` 维护项目级定位与共同设计原则；具体功能需求、候选方案和验收维护在 `.scratch/<feature>/spec.md`。ADR 聚焦已确定的架构选择、约束与理由，通过链接关联对应 Spec，不重复维护完整功能契约或实施进度。
