# 原生工具访问外部知识库规格

Status: ready-for-agent

创建日期：2026-11-03。清理阶段已移除文件 MCP 专用采集及活动安装材料，保留通用 MCP；当前知识来源为未采集，新参数尚未开发。需求与验收入口已确认；本文件描述待实施行为，不代表当前 CLI 已支持新参数。

## 问题陈述

审查人员需要模型按需阅读外部框架知识和项目约定，同时准确审查指定 Git 范围。此前文件知识库通过 MCP 提供读取和搜索，OCR 自身也提供类似工具，但两套工具的目录范围、参数和版本语义不同。模型容易选错工具、猜错路径，或给文件 MCP 传入未生效的行号参数；失败纠正和意外全文读取增加请求及上下文消耗。旧专用采集已清理，新原生入口尚未开发。

2026-11-03 的真实审查中，文件 MCP 共调用 334 次，其中 42 次失败；12 次文件读取携带服务未声明的行号参数。知识索引读取 57 次，同一审查分组内完全相同的 MCP 调用重复 53 次。这些现象说明接入方式需要简化，但不能把全部消耗归因于 MCP：多分组、第二轮审查和上下文累计发送也会增加成本。

用户希望用独立参数直接指定知识库目录，统一使用 OCR 原生工具查阅，不再为文件知识库配置额外服务。开发顺序是先清理已经被替代的知识库专用功能，得到可回归的干净状态，再实现新能力；不能通过整体回退破坏已有审查与报告功能。

## 解决方案

在 `ocr review` 中增加 `--knowledge-dir <目录>`。该参数将指定目录作为只读知识库提供给智能体；模型使用已有的 `file_read`、`file_find` 和 `code_search` 按需查阅，不再需要另一套文件读取工具。

沿用 OCR 的提示词组织方式：系统提示词用英文解释知识库的通用用途；具体目录放入当次任务的 `knowledge_bases` 区块。知识库是审查参考依据，不是审查目标，也不自动替代审查规则。业务背景可以提供知识索引和阅读重点，不要求固定索引文件，也不自动注入知识全文。

未提供知识库时省略区块；系统说明只需简短表达“未提供该区块表示没有配置额外知识库”，不重复说明其他上下文。目录不存在、不是目录或无法访问时，在发起审查模型请求前明确报错；有效但为空的目录允许使用。

## 用户故事

1. 作为审查人员，我希望通过一个目录参数提供知识库，以便无需安装和配置文件 MCP。
2. 作为审查人员，我希望知识库与业务背景分别提供，以便区分可查阅资料的位置与本次审查指引。
3. 作为审查人员，我希望在业务背景中指定可选索引文件，以便模型更快找到相关章节。
4. 作为审查人员，我希望未指定索引时仍能使用知识库，以便不受固定文件名和目录布局约束。
5. 作为审查人员，我希望模型使用同一套原生工具读取代码和知识，以便减少工具选择错误。
6. 作为审查人员，我希望原生按行读取对知识文件同样生效，以便避免为短章节读取整份长文。
7. 作为审查人员，我希望按文件名查找知识资料，以便模型无需反复猜测路径。
8. 作为审查人员，我希望按内容搜索知识资料，以便定位相关契约和示例。
9. 作为知识维护者，我希望未被 Git 跟踪或被 Git 忽略的知识文件也能查阅，以便独立维护资料。
10. 作为审查人员，我希望模型明确知道知识库是参考资料，以便不会把知识文档当作代码审查目标。
11. 作为审查人员，我希望分支和提交审查始终读取目标版本代码，以便不混用当前工作区内容。
12. 作为审查人员，我希望知识库位于仓库内部时也按知识资料读取，以便不依赖它存在于目标提交。
13. 作为审查人员，我希望知识库可以位于仓库外，以便多个项目复用独立资料。
14. 作为审查人员，我希望搜索和读取返回明确且可继续使用的路径，以便模型无需额外转换路径。
15. 作为审查人员，我希望索引内的相对链接以文档所在目录理解，以便正确定位相关章节。
16. 作为审查人员，我希望资料按需查阅，以便不因指定目录就自动遍历或全文加载知识库。
17. 作为审查人员，我希望没有配置知识库时保持原有审查行为，以便继续运行既有命令。
18. 作为审查人员，我希望空知识库不阻断审查，以便逐步补充资料。
19. 作为审查人员，我希望无效目录在模型调用前被发现，以便避免为配置错误消耗模型请求。
20. 作为审查人员，我希望只授权指定知识目录，以便不会因此开放整个磁盘的读取范围。
21. 作为审查人员，我希望知识目录只提供读取能力，以便模型不会修改参考资料。
22. 作为报告读者，我希望报告材料保留实际读取的知识来源与限制，以便能够追溯依据。
23. 作为报告读者，我希望局部读取、读取失败和实际应用被区分，以便不会把工具成功误认为完整核对。
24. 作为报告生成者，我希望已有报告 JSON 仍能生成 HTML，以便迁移知识接入不破坏既有成果。
25. 作为使用其他外部服务的用户，我希望通用 MCP 功能继续可用，以便文件知识迁移不影响其他集成。
26. 作为维护者，我希望先完成有明确范围的旧功能清理并回归，再开发新能力，以便定位变化与回退。

## 实现决策

### 命令与权限

- 首轮入口为 `ocr review --knowledge-dir <目录>`，适用于工作区、分支范围和单提交审查，与是否启用 `--report` 无关。首轮仅支持一个目录，不新增全局知识配置或多目录管理。
- 参数值是目录，不是文件正文、通配符或隐式规则文件。相对目录按命令调用时的工作目录解析，启动后使用规范化的绝对路径；目录名称和路径中允许空格及中文。
- 未传参数时不自动寻找约定目录，也不从业务背景或审查规则中的路径推导授权。
- 目录必须存在、是目录且可访问；启动检查在付费审查请求前完成。运行中资料消失或不可读时，按工具失败反馈，不虚构成功；允许继续有证据的审查并保留限制。
- 指定知识目录仅扩大只读资料访问范围，不增加写入工具，不扩大代码审查范围。目录外访问和通过链接逃逸的访问继续拒绝；优先复用已有路径规范化和授权校验。

### 同一套工具，两种内容来源

- 扩展已有原生读取、文件查找和内容搜索能力，不复制一套知识库专用工具，也不在各调用处分别维护路径例外。
- 被审查代码沿用现有版本语义：分支和提交审查读取目标 Git 版本，工作区审查读取既有工作区内容；目标版本缺少文件不能自动回退到磁盘。
- 明确指定的知识目录读取磁盘资料，不要求被 Git 跟踪，也不因目录位于仓库内部而读取目标 Git 版本。对于落在知识目录内的路径，知识资料语义优先。
- 知识目录位于仓库内部时，其文件不作为本次待审查目标，不计入代码审查覆盖；该参数不触发扫描整个知识目录。
- `file_read` 沿用现有行号参数、结果行号和截断提示；`file_find` 与 `code_search` 能查找、搜索知识目录中的未跟踪或被忽略资料，并遵循原有结果规模控制。
- 模型可以通过知识文件的明确路径定向操作；查找和搜索结果提供可直接用于后续读取的路径。普通源码请求沿用现有路径含义，不能把未找到的源码请求无提示地转成知识资料。
- 索引内相对链接以所在文档目录解析；通过提示和明确结果路径帮助模型定位，不新增递归 Markdown 抓取或自动全文注入。

### 提示词契约

- 复用现有计划与主审查消息的组织方式，提供独立 `knowledge_bases` 区块；当次目录只出现在任务资料区块中，不拼进系统提示词。
- 系统提示词新增英文通用说明：区块中的目录提供参考知识；用于理解框架契约、项目约定和审查依据；不是审查目标；可通过原生工具按需查阅；不要求遍历全部资料；最终问题仍定位到被审查代码。
- 未提供区块时的英文说明保持简短，只表达未配置额外知识库，不列举或解释其他上下文。
- 未配置知识库时省略整个区块，不保留空目录、占位路径或读库要求；有效空目录与未配置目录有所区分，但不要求模型反复寻找不存在的资料。
- 审查规则表达检查标准，业务背景表达当次指引，知识库提供参考资料；知识库中的示例或建议不自动提升为全部强制规则。
- 业务背景可以要求先读某个索引、重点核对特定契约；索引名称和阅读顺序不硬编码到产品。
- 沿用已有智能体循环、第二轮审查策略、上下文容量和压缩机制。知识目录及用途属于任务初始信息，不因历史工具消息压缩而丢失；不新增专用压缩阈值或另一个重试循环。

### 来源记录与兼容

- 延续既有知识来源记录目标：记录实际访问的资料、读取范围或局部性、摘要或标识、读取结果与限制，不能伪装成 MCP 调用，也不能仅因工具读取成功就声明知识已经正确应用。
- 复用现有会话及报告材料收集入口，优先作最小兼容扩展；如需增加来源类型等字段，保持已有材料的可读取性，不另建一套知识报告。
- 未使用 `--report` 时新知识访问能力仍可用；使用时知识依据进入报告材料。报告阶段继续消费已有材料，不新增知识库补读。
- 保留既有资料变化披露要求；恢复审查时不得在知识配置不兼容的情况下无提示复用旧任务，沿用现有恢复校验入口，不建立新的资料管理系统。
- 通用 MCP 的配置、动态工具、参数反馈和其他服务集成继续保留。新原生知识入口不自动启用文件 MCP，也不要求模型同时使用两套文件知识工具。
- 不自动删除用户现有 MCP 配置、卸载第三方包或改写知识文件。切换示例应说明原文件 MCP 无需再为该用途启用；用户显式配置的外部服务仍按原配置生效。

### 先清理，再开发

- 第一阶段先列出被新方向替代的知识库专用实现、配置示例、测试、复测脚本和文档，再按职责决定删除或改写；清理范围可通过差异审查，不使用整批提交回退代替功能判断。
- 清理的是文件知识库对 MCP 的专用依赖和已经失效的假设，不是删除全部 MCP、全部知识来源记录或全部历史工单。仍被其他能力使用的逻辑保留；来源记录为迁移整理，不能以清理为由永久丢弃。
- 保留原生审查、报告材料、HTML 智能体循环、草稿读取与编辑、通用工具反馈等有效能力；不删除用户知识目录、真实报告、会话或用户配置。
- 清理阶段允许暂时没有新的原生知识入口，但必须明确这个过渡状态，完成基线回归后再开发新能力；不能把旧入口已经移除写成新功能已经完成。
- 开发阶段按本 Spec 实现知识目录授权、原生工具支持、提示词和来源记录，并同步迁移使用入口与验收材料。两阶段分别保留可审查、可回退的改动边界。

## 测试决策

验收入口已由用户确认：以真实 CLI 加可控模型为主，观察参数、模型收到的消息、真实工具结果、报告材料和退出行为；底层只补必要的路径越界测试。优先复用已有命令集成测试、原生工具版本读取测试和知识观测测试模式，不为测试建立平行执行框架。

1. 未传参数时运行既有审查：不出现知识库区块，不改变既有代码读取和审查范围，不自动启动文件知识 MCP。
2. 临时创建独立知识目录，通过实际 CLI 让可控模型调用原生工具查找、内容搜索、按行读取；断言真实返回内容符合夹具，读取失败必须使测试失败，不能只交预制结果。
3. 直接观察计划和主审查请求：目录在任务知识库区块中，通用用途说明为英文，具体路径不在系统提示词；未配置情形仅有简短通用说明。
4. 构造目标 Git 版本与当前磁盘内容不同的源码，同时准备未跟踪或被忽略的知识文件；确认代码读取及搜索对应目标版本，知识读取及搜索对应磁盘资料。覆盖分支、提交和工作区入口的适用路径。
5. 将知识目录放在仓库内且包含变更文件：确认它可按知识资料读取，但不计入待审目标与代码覆盖；目标版本不存在知识文件时仍可读取授权磁盘资料。
6. 覆盖绝对目录、相对目录、含空格与中文目录；无效、非目录和不可访问参数在模型请求前报错；空目录不导致错误或强制全文读取。
7. 通过同一工具入口尝试目录外读取、查找和搜索，以及链接逃逸；不返回未授权内容。对平台支持的链接类型使用少量直接测试验证实际路径行为，不只断言字符串前缀。
8. 知识文件超过读取上限时显示真实截断信息，继续按行读取可获得后续片段；不存在文件和运行中读取失败可纠正且保留失败事实，不扩大授权目录。
9. 触发已有共享压缩路径后继续查阅，确认知识目录及用途仍可用；沿用已有可控阈值测试方式，不为知识库增加新的上下文参数。
10. 启用 `--report` 后验证原生知识读取来源、局部性和失败限制进入材料；没有读取时不伪造读取记录，不把读取成功当作实际应用证明；既有报告 JSON 仍可用于 HTML 生成。
11. 清理前后回归无知识库的原生审查、通用 MCP 服务调用与错误反馈、报告材料生成及 HTML 草稿编辑交付；测试目标是用户可见能力，不要求保留已废弃实现结构。
12. 自行运行小范围真实模型功能测试时显式使用 `--effort low`，配合单并发及已有累计预算限制，验证按索引渐进查阅、真实工具结果、来源保留及范围正确性。记录失败和重复读取；本阶段不以审查效果、知识应用质量、固定 token 降幅、零工具失败或固定问题数作为通过条件，也不为改善效果提高 effort 或反复付费运行。

### 常用真实样本与可复用背景

- 使用[资源索引中的常用样本](../../project-docs/review-resources.md#原生知识库常用验收样本)：XR 前端 `jk_web` 的 `dev-1010...dev-1016`，配合该仓库的 `.ai_knowledge`。用户已指定这组较小差异，不以最近的高成本大范围审查作为默认测试。
- 仓库与知识库绝对地址、完整分支提交及差异规模集中维护在资源索引；每次验收核对引用，记录真实范围和 OCR 实际覆盖。
- 通过 `--background-file` 复用 [XR 审查 background](../../project-docs/retests/knowledge-access/xr-review-background.md)，包含风险检查、知识索引和章节路由、误报排除及查阅边界，不包含原 Skill 的报告生成流程，也不把业务规则写入产品系统提示词。
- [复测入口](../../project-docs/retests/knowledge-access/README.md#原生知识库迁移的常用样本待实现)提供新参数实现后的命令，使用单轮、单并发和累计预算控制测试成本。预算截断的结果用于验证流程，不冒充完整审查通过。

## 不在范围内

- 修改上游分组算法、审查轮数、默认预算或模型上下文阈值；测试时可使用已有参数限制成本。
- 新增运行时用量展示、费用估算、监控面板或自动成本策略；按用户决定后置。
- 跨组或跨轮共享记忆、自动去重读取、向量检索、RAG、资料索引服务或自研文件 MCP。
- 全面重写或拆分业务知识库；后续根据原生工具实际读取效果单独评估。
- 多知识目录管理、全局默认知识配置、额外索引参数和知识管理界面。
- 首轮为 scan、delegate、编辑器扩展或 report 增加同名参数；共享工具改动仍需保证这些现有调用不回归。
- 删除通用 MCP、恢复 HTML 内容审查或改变报告生成架构。
- 本次写 Spec 即执行清理、回退、提交、删除旧工单或修改用户环境。

## 补充说明
