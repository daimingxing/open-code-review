# 02：知识来源进入报告材料并完成功能验收

**What to build:** 审查人员使用原生知识目录和 `--report` 后，报告材料可追溯实际查阅的知识、局部读取、失败与资料变化限制；恢复任务保留已有依据，旧报告 JSON 继续可用，并通过低成本真实模型测试确认完整功能链路。

**Blocked by:** 01：原生知识目录参与审查。依赖其目录授权、实际工具访问事实和恢复兼容校验，不能以模拟 MCP 记录替代。

**Status:** ready-for-agent

**完成状态：** 已完成（2026-11-03）。

需求依据：[原生知识库 Spec](../spec.md)中的来源记录与兼容、测试决策及真实样本。延续已保留的报告材料契约；不恢复旧文件 MCP 专用采集，不修改 HTML 生成架构或加入 HTML 审查规则。

- [x] 消费工单 01 的实际访问事实，将原生知识来源写入 `knowledge_sources`；优先最小兼容扩展既有材料，不另建知识报告，也不将原生工具记录伪装为 MCP 调用。
- [x] 区分目录已配置、仅查找或搜索、实际读取、局部读取、截断和读取失败；保留来源、实际范围、摘要或标识、结果与限制。不能仅凭工具成功声称全文读取或知识已经正确应用。
- [x] 未配置目录、没有实际读取、读取部分成功及全部失败均有真实状态与原因；不能继续无条件返回迁移期的未采集说明，也不能把空记录当作已完成知识核对。
- [x] 披露实际访问资料的可识别变化；生成材料时不得用后来的磁盘内容冒充审查时读取的版本，也不得为补来源重新读取全部知识。
- [x] 恢复审查保留复用结果已有的知识依据，并记录本次新增访问及限制；旧会话缺乏来源证据时明确说明，不补造历史记录。知识配置不兼容仍由原有恢复校验拒绝。
- [x] 在成功、预算截断、取消和模型失败等既有材料交付路径中保留已获得的知识事实，遵守原有退出、覆盖和部分结果语义；不把审查未完成展示为完整通过。
- [x] 不使用 `--report` 时原生知识访问继续正常工作；启用时报告生成阶段只消费已有材料，不再读取目标代码或知识目录补证据。
- [x] 旧报告 JSON 仍可读取并生成 HTML；当前材料、旧材料及含新增知识来源的材料均覆盖兼容回归，HTML 循环、草稿读取编辑及上游收尾完成语义保持有效。
- [x] 通过真实 CLI 加可控模型覆盖上述来源、局部性、失败、变化、恢复和兼容行为，直接断言工具结果及材料内容，不依赖固定 DOM、固定问题数量或另一个测试执行框架。
- [x] 使用 Spec 引用的常用 XR 样本和可复用 background 做一次预算受控的真实模型功能测试，显式使用 `--effort low`、单并发及已有累计预算限制；不默认改用高成本大范围样本，不为改善审查效果提高 effort 或反复付费运行。
- [x] 真实模型测试记录所测版本、完整 Git 引用、实际覆盖、知识访问与材料结果、失败和重复读取。验收关注按索引查阅、工具链路、来源保留和范围正确性，不评价审查效果，不要求固定 token 降幅、零工具失败或固定问题数；预算截断结果不冒充完整审查通过。
- [x] 同步活动使用文档、复测入口及相关架构决策的迁移状态，区分计划、已实现和已验证。旧审查与报告 Spec 作为历史规格保留，不重新日常维护，也不重新创建已完成的清理工单。
