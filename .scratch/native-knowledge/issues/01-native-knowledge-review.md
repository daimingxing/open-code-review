# 01：原生知识目录参与审查

**What to build:** 审查人员通过 `ocr review --knowledge-dir <目录>`，在工作区、分支范围和单提交审查中使用原生工具按需查阅知识；代码继续对应实际审查版本，知识资料读取授权目录中的磁盘内容，恢复审查不会无提示复用知识配置不兼容的任务。

**Blocked by:** 无，可立即开始。

**Status:** ready-for-agent

需求依据：[原生知识库 Spec](../spec.md)中的命令与权限、内容来源、提示词、来源记录与兼容。以 `66fb4fc` 的清理和上游集成结果为基线；旧文件 MCP 专用采集已经删除，不重复清理，也不恢复旧观测机制。

- [ ] 新参数仅增加到 `review`，首轮支持一个目录；不依赖 `--report`，不新增全局配置、知识专用工具或其他命令入口。
- [ ] 相对目录按命令调用目录解析，接受绝对路径、空格和中文。不存在、非目录或不可访问的输入在审查模型请求前报错；有效空目录可用。未传参数不自动发现目录，也不从背景或规则推导授权。
- [ ] 复用原生 `file_read`、`file_find` 和 `code_search`，统一处理知识目录授权。读取、查找和搜索均限制在既有代码权限及明确授权的知识目录内，不增加知识写入能力；拒绝越界及链接逃逸。
- [ ] 知识文件读取磁盘内容，包含未跟踪和被 Git 忽略的文件；查找、搜索不得仅复用 Git 跟踪文件列表而遗漏这些资料。返回路径可以直接用于后续工具调用。
- [ ] 按行读取、行号、截断信息、查找与搜索结果规模控制保持可用；长文件可继续分段读取，不把局部结果表述为全文。
- [ ] 分支和单提交审查的源码读取、查找与搜索仍对应目标 Git 版本，保持上游固定提交的语义；目标版本缺少源码时不回退磁盘或知识库。工作区审查保留既有语义。
- [ ] 仓库内知识目录优先按知识资料处理；其中的变更不作为代码审查目标，也不计入代码覆盖。正常执行与恢复校验使用相同的范围排除规则。
- [ ] 计划及主审查任务消息提供 `knowledge_bases` 区块；具体路径不进入系统提示词。新增系统说明使用英文，解释参考用途、按需查阅和非审查目标，不把知识中的全部建议提升为强制规则。
- [ ] 未配置知识库时省略区块，系统说明只简短表达没有额外知识库；不添加空路径或固定索引要求。背景中的可选索引和阅读指引继续有效，相对链接按文档所在目录理解。
- [ ] 沿用共享智能体循环、轮次和压缩阈值；真实触发共享压缩后仍能继续查阅，知识目录和用途不丢失，不另造压缩或重试机制。
- [ ] 在现有会话链路中保存实际知识访问事实，供恢复校验及工单 02 消费：来源、操作结果、读取范围或局部性、截断及可用的内容标识和限制。仅查找或搜索不伪装为阅读全文，读取成功不等于已正确应用。
- [ ] 恢复校验识别知识库的新增、移除或目录变更，不在配置不兼容时复用旧结果；复用已有校验入口及拒绝前不创建新会话的约束。无知识库的旧会话继续按既有兼容规则处理，不凭空补造访问记录。
- [ ] 不因记录来源而在启动时递归读取知识全文；运行中资料读取失败可反馈模型纠正，并保留真实失败。资料变化和恢复时已有依据的保留方式可供工单 02 使用，不另建资料管理系统。
- [ ] 主要通过真实 CLI 加可控模型验证三个审查入口的真实查找、搜索和分段读取结果、提示词位置、覆盖、恢复及失败退出；测试必须检查工具返回内容，不能只提交预制审查结果。底层仅补必要的真实路径越界和链接测试。
- [ ] 回归未配置知识库的审查、通用 MCP 分页与参数反馈、既有 `scan`、`delegate` 及报告调用涉及的共享工具行为；保留报告材料和 HTML 循环、草稿编辑能力。本工单结束时报告知识字段仍可明确为未采集，正式接入由工单 02 完成。
- [ ] 同步新增参数的必要帮助和用法，说明当前交付范围，不把报告来源记录写成已经完成。
- [ ] 自行运行真实模型功能测试时显式使用 `--effort low`，配合单并发和已有预算控制；以流程、工具结果、范围和失败语义验收，不以问题数量、准确率或知识应用质量为门槛，不为改善审查效果提高 effort 或反复付费运行。
