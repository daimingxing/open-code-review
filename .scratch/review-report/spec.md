# 外部知识驱动审查与多仓库 HTML 报告规格

日期：2026-09-30。本文件集中维护“外部知识驱动审查与多仓库 HTML 报告”功能的需求、行为契约和验收标准，遵循[项目级设计原则](../../project-docs/project-design.md)。

Status: ready-for-agent

产品行为、测试边界及工单拆分均已确认，按[本地工作事项约定](../../project-docs/agents/issue-tracker.md)管理；9 张工单见[实施索引](README.md)。Status 是分诊状态，不表示功能已实现或依赖已完成。

## 问题陈述

用户需要在 OCR 内独立完成前端、后端等仓库的代码审查，依据外部维护的规则和框架知识减少误报，再将多个独立审查结果整理为清晰、美观的中文 HTML 报告。

现有工作依赖多个 Skill、Markdown 中间文件和人工串联。知识资料不一定存在于被审查的 Git 提交中，而全文注入大型知识库会占用大量上下文。原生结果与会话页面也不能直接满足多仓库成果、人员、风险和覆盖情况的汇报需求。

产品需复用原生 OCR 的审查、规则和 MCP 接入能力，并保留原有用户的命令行为。具体业务规则和知识不能硬编码进产品，后续 UI 应管理同一套资料与流程。

## 解决方案

采用三个顺序实施、分别验收的阶段：

1. **规则与知识读取**：沿用 `ocr review` 与 `--rule`；规则声明知识索引和查阅要求，通过现成文件 MCP 服务读取相关章节。知识库独立于业务仓库和 Git 历史；小型知识库可直接引用 Markdown 作为后备方案。
2. **报告材料**：为 `ocr review` 增加可选 `--report`，输出独立、版本化的报告 JSON，保存生成报告所需的事实、证据、统计、覆盖、成果材料和中文说明。
3. **HTML 报告**：新增同级 `ocr report`，读取一份或多份报告 JSON 和命名模板，允许模型组织内容及生成 HTML，程序负责校验和保存。报告不重新访问代码、Git 或知识库，不进行第二次审查。

报告采用下文约定的九类内容，按材料条件展示，不为填满章节编造事实。首版在本地运行，使用用户准备好的 Git 仓库；认证、拉取与分支同步由用户负责。以下新增命令与参数为待实现契约，不代表上游当前能力。

2. 作为审查人员，我希望继续使用工作区、单提交和分支比较模式，以便按实际变更范围审查。

5. 作为知识维护者，我希望知识库独立保存并供多个仓库复用，以便不必把资料写入业务 Git 历史。
6. 作为审查人员，我希望模型先读索引再读相关章节，以便减少无关内容占用上下文。
7. 作为小型项目维护者，我希望少量知识可以直接通过 Markdown 规则引用提供，以便使用简单的后备方式。
8. 作为运行维护者，我希望复用现成文件 MCP 服务，以便不必开发或部署新的知识检索系统。
9. 作为运行维护者，我希望限制知识目录并只开放读取工具，以便模型不能修改资料或读取授权范围外的文件。

35. 作为报告读者，我希望未执行的结构检查显示为未提供，以便不会把数据缺失误读为没有问题。
36. 作为报告读者，我希望报告能离线打开、适配窄屏并便于打印，以便分享和阅读。
37. 作为报告生成者，我希望不兼容或缺少必要材料的 JSON 被明确拒绝，以便系统不会自行猜测缺失事实。
38. 作为审查人员，我希望审查部分完成时仍能保存带限制说明的材料，以便利用已经完成的工作。
39. 作为审查人员，我希望材料生成失败时原生结果仍被保留，以便新增阶段失败不破坏审查结果。
40. 作为报告生成者，我希望已有有效 JSON 时可以重新生成 HTML，以便更换模板或修复生成失败时不必重审代码。
41. 作为运行维护者，我希望知道各阶段模型耗时和用量，并限制失败修复次数，以便控制成本。
42. 作为后续 UI 开发者，我希望界面复用这些命令和资料关联，以便不建立第二套审查或知识管理机制。

## 实现决策

### 职责与扩展边界

- 复用原生 Git 范围选择、规则解析、模型配置、MCP 客户端、审查结果和覆盖信息；仅在报告材料收集、报告生成与输出保存处增加必要能力。
- 逻辑职责分为知识接入配置、报告材料收集、材料校验与汇总、HTML 生成与校验。职责划分不要求分别建立新包或抽象层，优先使用已有接口。
- 首版知识接入采用已验证的文件 MCP 服务。授权根目录由服务配置限定，非空工具白名单只开放读取能力；规则中的路径不会自动扩大授权。服务具备写能力不等于 OCR 向模型开放写工具。
- 知识库的选择保存在原生规则正文中，不新增知识命令参数、规则协议或知识管理系统。基础接入不要求修改 Go 代码。
- 记录实际读取的知识及版本或摘要；同次审查保持资料版本一致，或检测并披露变动。读取成功不代表知识一定被正确应用。
- 本功能采用外部 `@modelcontextprotocol/server-filesystem`，OCR 作为 MCP 客户端；配置与已有证据见[规则与知识读取](../../project-docs/open-code-review/rules-and-context.md)。同一授权根目录内切换知识库通常只需调整规则；当次业务需求仍走原生 `--background` 或 `--background-file`。
- 知识索引说明用途、适用版本和路径，相对链接以索引所在目录解析；只读头尾不能声称已读全文，长文档可按章节拆分。历史代码不得因目标 Git 版本缺少文件而回退到当前磁盘。
- 小型 Markdown 直接注入是否适用取决于实际 Token 预算；拆成多份后仍全部注入不会减少上下文，直接引用也不会递归读取链接文档。

### 命令契约

- `ocr review` 未传 `--report` 时保持原有行为；裸参数启用自动命名，带值时使用指定路径。必须支持空格分隔和正常的路径引号，不要求等号。
- 下一个参数是选项或命令结束时识别为裸参数；不吞掉后续选项，不接受无法解释的多余位置参数。若底层解析不能可靠满足该行为，应反馈取舍，不能私自更改语法。
- 报告 JSON 独立于原生输出，不要求同时指定 `--format json`，不修改原生输出格式或保存语义。
- 自动 JSON 名称包含仓库、模式/范围和审查启动时本地时间，保存到被审查仓库根目录。单提交用提交标识，分支比较用双方标签，工作区用工作区标签；完整 SHA、比较起点、工作区快照及带时区时间另存材料。
- 文件名片段清理非法字符和空格，截短过长标签，保留时间与后缀。自动名称冲突时递增编号并排他创建；显式路径存在时拒绝覆盖，父目录缺失时明确报错。报告材料与原生输出指向同一文件时拒绝执行冲突保存。
- `ocr report` 至少接受一份 `--input`，该参数可重复，输入顺序用于仓库展示。首版只生成 HTML，不另建合并 JSON。
- `--template` 可省略。首个模板名称为 `review-summary`，默认选择指向该名称；未知名称报错。模板约束章节、视觉风格和交互，可提供布局参考，不要求固定 DOM。
- `ocr report --output` 指完整文件路径；省略时按当前命令目录及日期生成 HTML 名称，适用相同的自动编号和显式防覆盖规则。

### 文件命名与保存细则

报告 JSON 默认文件名为 `<仓库名>__<审查范围>__<YYYYMMDD-HHmmss>.report.json`，仓库名取根目录名，时间取审查启动时本地时间；完整时间与时区另存材料。

| 审查模式 | 默认名称示例 |
|---|---|
| 分支比较 | `2dgis-f__main-to-feature-login__20260930-213305.report.json` |
| 单提交 | `2dgis-f__commit-4b588a3__20260930-213305.report.json` |
| 工作区 | `2dgis-f__workspace__20260930-213305.report.json` |

文件名用于识别，材料保留原始引用、完整 SHA、实际比较起点或工作区快照。空格、控制字符及 Windows 非法字符替换为 `-`；超长片段截短并保留时间和后缀，恢复运行沿用原审查范围描述。

HTML 缺省名称为当前命令目录中的 `report-yyyy-mm-dd.html`，不从多份输入中推断归属仓库。默认名称冲突时，由程序使用排他创建递增编号，例如 `…(1).report.json`、`report-2026-09-30(1).html`；系统不会代为实现这套编号规则。显式路径不自动改名，按命令契约拒绝覆盖或缺失父目录。

### 数据契约与汇总

- 报告 JSON 带版本，只接收本功能生成且兼容的材料，不直接接受原生 OCR JSON 或任意第三方 JSON。
- 材料保存运行身份、仓库、真实范围、最终问题、稳定问题标识、代码位置、等级、证据、建议、覆盖与失败原因、Git 统计、模块和人员成果依据、知识来源及必要中文说明。
- 优先复用原生字段和 `critical/high/medium/low` 语义，JSON 键与技术标识不汉化。保留原始英文说明并在材料阶段准备中文展示内容；不增加任意外部材料翻译能力。
- JSON 约束事实和证据，不对应页面 DOM。具体字段、版本编码与可选字段在第二阶段细化，但必须覆盖本规格的用户可见行为。
- 同仓库不同范围作为不同审查单元，重复运行输入报错，重叠范围不简单相加为去重总量。区分最终差异与逐提交累计；工作区不伪造提交数，不将未提交修改归于 HEAD 作者。
- 跨仓库仅按可靠身份去重人员。Git 作者、提交者与推送者不混用；问题关联人员不等于缺陷责任人，增删行不代表工时或绩效。
- 同一问题一个标识，结构等章节引用该标识，不能重复计数。治理项和未确认事项不混入确认缺陷；未知、缺失和确认为零分别展示。
- 保留原始问题集合；若用户明确排除问题，展示统计统一使用同一可见集合，并保留排除依据。

### 报告内容

首个命名模板 `review-summary` 按以下要求组织内容；材料缺失必须如实表达。

| 顺序 | 内容与要求 |
|---|---|
| 1 | 报告概览：标题、仓库、范围、执行时间及是否存在未完成审查 |
| 2 | 质量与覆盖：四级风险数量、仓库分布、选中/完成/失败/跳过情况 |
| 3 | 问题明细：按风险排序，支持仓库/等级/类别筛选和详情折叠；展示位置、触发条件、影响、证据、建议及必要来源 |
| 4 | 仓库变更概览：文件、增删行、提交、作者与范围说明 |
| 5 | 模块与工作成果：依据 JSON 中的成果材料、代表文件与提交组织说明 |
| 6 | 人员工作明细：参与者、相关提交、文件、模块及问题关联依据 |
| 7 | 项目结构与治理：仅展示已有检查材料，本次问题与存量治理分列；没有数据时说明未提供，不能展示为无问题 |
| 8 | 未确认事项与限制：知识未读取、检查未完成、文件跳过、验证未执行等 |
| 9 | 来源与统计口径：材料版本、运行标识、规则与已读知识来源、模板和生成时间；不暴露凭据或无必要的本机绝对路径 |

### 模型生成 HTML

- 报告模型仅使用输入 JSON 和所选模板，不访问代码、Git、知识库、会话或网络资料，不重新审查。允许为生成 HTML 调用模型 API。
- 模型可重组表达、概括已有成果并生成完整 HTML；不得新增缺陷、改变严重等级、编造统计或推造缺失成果。程序计算并核验可靠数字与问题集合，自动校验不等于完全消除模型事实错误。
- 按九类内容及材料条件展示报告；缺少结构检查时明确未提供，无治理建议时不生成空卡片，不单列回归建议章节，问题建议保留在问题详情。
- HTML 保持离线单文件，支持窄屏、打印、问题筛选和折叠；合理使用留白、层次及图表。信息不只依靠颜色表达，不加载外部资源，不暴露凭据或无必要的本机绝对路径。
- HTML 初版只固定可复核的底线：九个必要章节均有可见内容；每条输入 finding 在问题明细中出现一次，显示中文说明、严重程度、文件和行号；源代码与证据或未采集原因完整呈现且不改写；基础风险与覆盖统计与材料一致。标题、标签、措辞及布局可不同，不要求固定 DOM 或逐项事实标记。章节遗漏、问题遗漏或重复、定位与等级错误、证据缺失或错配、统计不一致时不接受。
- 对输入证据和动态文本进行安全处理，避免代码片段或说明被当作可执行内容。输出校验需检查必要章节、完整问题集合、主要事实、基础统计、离线文件有效性与安全；对真实报告进行浏览器验收。仅当超出 JSON 已知数字的叙述明确带入新数值时，自动校验器可据此拒绝；其他自然语言事实仍需结合真实报告人工核对。
- 初版不以视觉精致、非关键标签一致、所有非问题材料事实逐项出现或措辞逐字一致作为失败条件；后续可依据实际成品再决定将哪些稳定需求交由代码实现。
- 相同材料的事实应一致，措辞和布局可以不同，不要求输出逐字节相同。生成和修复有次数或预算上限，不能通过截断问题列表让长报告通过。

### 失败、重试与默认行为

- 知识不可用时保留已完成的代码审查，报告披露相关限制；首版不增加必需知识失败即强制中断的策略。
- 审查部分完成时允许保存明确标记的材料并生成有限结果报告，不能把完全失败、跳过或空问题数组等同于通过。
- 原生审查成功而材料阶段失败时，保留原生结果，返回非零并说明阶段。
- 首版不新增“仅重做材料”的专用命令；现有模式支持恢复时评估复用，否则明确需重新运行，不假定工作区支持恢复。
- 材料版本不兼容或必需内容缺失时明确报错。HTML 无效、遗漏问题或数字不一致时保留诊断，不发布成功成品，也不覆盖已有有效文件。
- 已有有效 JSON 时，可重新运行 `ocr report`，无需重审代码。材料整理和 HTML 生成分别记录模型用量，避免无必要的重复整理。

## 测试决策

### 测试边界（已确认）

用户已确认主要从 CLI 的可观察行为验收：参数、退出状态、stdout/stderr、生成文件及其内容。用临时 Git 仓库、隔离配置、可控模型服务和真实文件 MCP 服务构成测试环境；不模拟每个内部函数，也不按实现私有结构断言。

复用现有模型客户端边界替换外部模型，在自动测试中稳定控制响应、工具调用、超时和错误。真实模型的知识选读与应用效果另做验收，不能由模型替身测试代替。仅对 CLI 难以稳定覆盖的并发保存等行为，在已有文件输出边界补充最小测试。

### 现有测试先例

- 原生结果输出已有 `TestEmitRunResult_JSONWithComments`、`TestEmitRunResult_JSONNoFiles` 和 `TestEmitRunResult_JSONIncludesToolFailureArguments` 等测试，可参考其结果提供者替身和可观察输出断言。
- `TestEmitRunResult_TextPartialNeverLooksGood` 已验证部分结果不能被描述为良好完成，可沿用其状态展示原则。
- `TestManifestFlowCompleteAndPartial`、`TestManifestFlowBudgetAndSkipped` 及恢复相关集成测试，可参考覆盖、预算、部分失败与运行身份的验证方式。
- 已有临时 OCR/MCP 验证使用本地模型替身成功触发索引读取、章节读取和目录外拒绝；应复用这种边界，不能把该实验等同于正式回归或真实模型效果验收。

### 验收矩阵

| 范围 | 对外行为与通过条件 |
|---|---|
| 原生兼容 | 不传 `--report` 时，既有模式、格式、输出路径和退出行为保持兼容；原生 JSON 与报告 JSON 可独立生成，互不覆盖 |
| 参数解析 | 裸参数、带路径、空格路径、参数顺序及相邻选项均按契约处理；多余参数明确报错 |
| 知识接入 | 能从授权目录读取索引及链接章节；只暴露读取工具；目录外和父目录访问拒绝；代码仍按目标版本取证 |
| 知识实际应用 | 真实模型样例覆盖依赖知识才能判定的问题和应排除的误报；核验工具记录、引用章节及结论，而非只检查是否调用工具 |
| 知识失败 | 服务不可用、文档不存在或返回不完整时，保留有效结果并明确限制，不伪造已查阅或全部完成 |
| 保存 | 三种审查模式的默认名称、非法字符、长标签、重名和并发编号正确；显式已存在路径、输出冲突、缺失父目录报错且不损坏已有文件 |
| 材料完整性 | 运行身份、实际范围、问题、覆盖、统计和中文材料可校验；成功、部分失败、跳过与确认为零可区分；材料失败不破坏原生结果 |
| 多份输入 | 单份、多份及输入顺序符合要求；重复同次结果拒绝；同仓库不同范围独立展示，重叠统计不误称去重总量 |
| 模板与语言 | 省略模板使用默认选择，未知名称报错；中文展示与原生技术标识同时保留；九类内容按条件出现 |
| 事实边界 | 生成报告时不读取仓库、Git、知识库或会话；模拟模型改等级、改数字、漏问题或补造材料时拒绝无效成品 |
| HTML 交付 | 九个必要章节有可见内容；每条 finding 一次且有中文说明、等级、文件与行号；输入源代码及证据或缺失原因可见且无遗漏错配；基础风险/覆盖统计正确；离线、安全、窄屏、筛选折叠、打印和长报告完整性通过。标题、标签、措辞、布局和 DOM 可变化 |
| 生成失败与重试 | 模型失败、预算耗尽或输出校验失败时明确诊断；修复有界；不覆盖有效文件，可用已有 JSON 重试生成 |

测试以外部行为与真实证据为依据，不要求固定模型措辞、CSS 类名、DOM 快照或调用次数。涉及代码实现时遵循仓库已有测试入口和检查要求；本次只生成规格，不执行产品实现测试。

## 不在范围内

- UI 壳、桌面客户端、远程部署、模型或仓库凭据管理。核心能力验收后再考虑本地 Web UI，前端优先采用 Vue.js；界面复用相同能力，页面、服务接口与配置管理在 UI 阶段细化。
- 自研 MCP、向量数据库、正文语义检索、自动索引系统或新的规则文件协议。
- 替代原生审查命令、修改原生输出语义、扩大到 `scan` 或委托模式。
- 新增时间范围审查、全仓库结构扫描、前后端联合接口审查或原 Skill 全部预检查脚本的迁移。
- 复刻原 Skill 的 Markdown 中间格式、固定 CSS、P1/P2/P3 或 HTML 校验器契约。
- 新增报告格式、模板管理 UI、更改默认模板的命令、任意第三方 JSON 导入或自动翻译。
- 单独重做报告材料的专用命令、知识不可用即强制中断策略、综合评分或自动合并阻断策略。
- 要求本轮立即实现功能，或把已有实验声明为生产能力完成。
