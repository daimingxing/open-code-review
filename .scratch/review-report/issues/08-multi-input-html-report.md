# 08：多份报告材料汇总为一份 HTML

阶段：3。规格来源：[Spec](../spec.md)；执行约定及依赖总览：[工单索引](../README.md)。关联用户故事：23、24、25、26、30、31、33、34。

## 交付行为

用户重复指定任意数量的输入材料，按输入顺序得到一份可区分审查单元、范围与统计的报告。

## 验收条件

- [ ] 支持一份、两份和更多材料，保持输入顺序；同一次运行的重复材料即使文件名不同也拒绝，不额外输出合并 JSON。
- [ ] 同仓库不同范围保持独立审查单元，重叠变更不简单相加为去重总量；多仓库统计明确口径，未知数据不默认为零。
- [ ] 可靠身份才能跨仓库合并人员，别名不确定性明确保留；问题和证据始终可追溯到所属审查单元，标识碰撞不会吞掉或串联问题。
- [ ] 报告的概览、风险、成果及人员内容支持多个审查单元，为 09 的多单元筛选保留清晰归属；结构或治理章节引用问题时不重复计数，不推断跨仓库接口缺陷。
- [ ] 通过 CLI 和浏览器验证输入重排、重复输入、同仓库重叠范围、混合完整与部分结果、多仓库人员及问题标识情况，沿用单份报告的事实、安全和保存约束。
